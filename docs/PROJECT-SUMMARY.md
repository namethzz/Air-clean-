# AirClean — แนวคิดและสรุปโครงการ

## 1. แนวคิดหลักของ AirClean

**AirClean คือแอปที่ทำให้การล้างแอร์เป็นเรื่องง่ายสำหรับทั้งลูกค้าและช่างแอร์**

ลูกค้าไม่ควรต้องเสียเวลาจัดการหลายเมนูเพื่อจองบริการ สิ่งที่ต้องทำควรเป็นการระบุสถานที่ เลือกงานที่ต้องการ ดูช่างที่เหมาะสม แล้วนัดหมายได้ง่าย ส่วนช่างควรเห็นงานที่เกี่ยวข้องกับพื้นที่ของตนเอง รู้รายละเอียดหน้างานและค่าตอบแทนล่วงหน้า และนำทางไปยังลูกค้าได้สะดวก

หัวใจของผลิตภัณฑ์จึงมี 3 เรื่อง:

1. **ค้นหาช่างให้เหมาะกับงานและสถานที่** — ใช้ตำแหน่งจริง พื้นที่ให้บริการ ประเภทงาน ราคา คะแนน และเวลาที่สะดวกเป็นข้อมูลประกอบ
2. **ทำให้การจองและติดตามเข้าใจง่าย** — ลดการกรอกข้อมูลที่ไม่จำเป็น เลือกจุดบนแผนที่ แก้ไขรายละเอียดที่อยู่ และดูความคืบหน้าของช่างได้
3. **ช่วยให้ช่างจัดการงานและเดินทางได้จริง** — ดูคิว รายได้โดยประมาณ ประเภทที่พัก จำนวนเครื่อง และเปิดเส้นทางไปยังหน้างานได้

สมุดประวัติประจำเครื่อง รายงานบริการ และการจัดการงานหลายเครื่องเป็นฟังก์ชันสนับสนุน ไม่ควรบังคับให้ลูกค้าต้องใช้งานก่อนจองบริการตามปกติ

## 2. ประสบการณ์ของ Customer — ลูกค้า

เป้าหมายของลูกค้าคือ **อยากล้างแอร์และหาช่างที่เหมาะกับตนเอง โดยไม่ต้องวุ่นวาย**

### ขั้นตอนที่ควรเป็น

1. **ระบุสถานที่:** ใช้ตำแหน่งปัจจุบันหรือแตะเลือกตำแหน่งบนแผนที่
2. **ยืนยันที่อยู่:** กรอกหรือแก้ไขบ้านเลขที่ ซอย ถนน ชื่ออาคาร ชั้น ห้อง และจุดสังเกตได้ตามชนิดสถานที่
3. **บอกรายละเอียดงานเท่าที่จำเป็น:** ประเภทบริการ จำนวนเครื่อง และวันเวลาที่สะดวก
4. **ดูช่างที่เหมาะสม:** แสดงข้อมูลที่ช่วยตัดสินใจ เช่น ระยะทางหรือพื้นที่ให้บริการ ราคา คะแนนรีวิว ประเภทงานที่รับ และเวลาว่าง
5. **ยืนยันการจอง:** เห็นสรุปงาน ที่อยู่ วันเวลา และราคาโดยประมาณก่อนยืนยัน
6. **ติดตามช่าง:** เมื่อช่างเริ่มเดินทาง ลูกค้าเห็นตำแหน่งบนแผนที่และควรเห็นเส้นทางถนนที่เข้าใจได้
7. **หลังบริการ:** ตรวจรายงาน ยืนยันการชำระเงิน และให้คะแนนหรือรีวิวได้หากต้องการ

### ข้อมูลที่อยู่

บ้านเดี่ยวอาจต้องใช้เพียงบ้านเลขที่และรายละเอียดทางเข้า ส่วนคอนโดหรือหอพักควรเพิ่มชื่ออาคาร ชั้น และเลขห้อง ลูกค้าควรแก้ไขรายละเอียดได้แม้จะเลือกตำแหน่งจากแผนที่แล้ว เพราะหมุด GPS อย่างเดียวอาจไม่บอกทางเข้าหรือเลขห้อง

## 3. ประสบการณ์ของ Technician — ช่างแอร์

เป้าหมายของช่างคือ **รู้ว่ามีงานอะไรใกล้ตัว คุ้มค่าหรือไม่ และไปถึงลูกค้าได้โดยไม่หลง**

### หน้ารวมงานที่ช่างควรเห็น

- งานวันนี้และงานที่อยู่ในพื้นที่ใกล้เคียง
- พื้นที่หรือระยะทางจากตำแหน่งช่าง
- ค่าตอบแทนหรือราคางานโดยประมาณ และรายละเอียดว่าใครเป็นผู้กำหนดราคา
- ประเภทที่พัก เช่น บ้านเดี่ยว คอนโด หรือหอพัก
- จำนวนเครื่องแอร์และประเภทบริการ
- วันเวลา นัดหมาย และรายละเอียดการเข้าพื้นที่ที่ลูกค้าให้ไว้
- สถานะของงาน เพื่อแยกงานใหม่ งานที่รับแล้ว งานที่กำลังเดินทาง และงานที่เสร็จแล้ว

### ขั้นตอนหลังรับงาน

1. เปิดรายละเอียดและตรวจสอบค่าตอบแทน สถานที่ จำนวนเครื่อง และวันเวลา
2. รับงานตามกติกาของระบบ
3. กดนำทางเพื่อเปิดแอปแผนที่ เช่น Google Maps โดยส่งพิกัดปลายทางที่ลูกค้าปักหมุดไว้
4. อัปเดตสถานะการเดินทาง และแชร์ GPS ระหว่างเดินทางเมื่อได้รับอนุญาต
5. เมื่อถึงหน้างาน ทำรายการตรวจเช็กและบันทึกรายงานบริการ
6. ยืนยันการชำระเงินร่วมกับลูกค้าและปิดงาน

ข้อมูลที่สำคัญควรเห็นได้จากหน้ารวมงานทันที โดยไม่ต้องเปิดหลายหน้าเพื่อรู้ว่างานอยู่ที่ไหน ล้างกี่เครื่อง หรือได้ค่าตอบแทนเท่าไร

## 4. บทบาทสนับสนุนอื่น

### Manager — ผู้ดูแลอาคาร

เหมาะสำหรับอาคารหรือสถานที่ที่ต้องล้างหลายเครื่องพร้อมกัน สามารถส่งคำขอแบบกลุ่ม ระบุจำนวนเครื่อง ที่อยู่ และกำหนดวันนัดหมาย แล้วติดตามความคืบหน้าของงานได้ ฟังก์ชันนี้เป็นกรณีใช้งานเฉพาะ ไม่ควรทำให้การจองปกติของลูกค้าซับซ้อนขึ้น

### Admin — ผู้ดูแลระบบ

ทำหน้าที่ดูแลข้อมูลและสิทธิ์ในระดับระบบ เช่น การตรวจสอบบัญชีช่าง ดูรายการจอง และจัดการเหตุขัดข้อง การกำหนดบทบาท Admin ต้องทำผ่านช่องทางที่ได้รับอนุญาต ไม่ใช่ให้ผู้ใช้สมัครเป็น Admin เอง

## 5. ฟังก์ชันสนับสนุน

### สมุดประวัติประจำเครื่อง

เก็บประวัติการให้บริการและรอบบำรุงรักษาของเครื่องปรับอากาศ เพื่อให้ลูกค้ากลับมาดูย้อนหลังหรือวางแผนล้างแอร์ครั้งต่อไปได้ แต่ควรเป็นทางเลือกเสริม ลูกค้าใหม่ยังสามารถจองล้างแอร์ได้โดยไม่ต้องสร้างทะเบียนเครื่องก่อน

### รายงานบริการ

ช่างสามารถบันทึกรายการตรวจเช็ก เช่น แผ่นกรอง คอยล์ และท่อน้ำทิ้ง รวมถึงสรุปงานและลิงก์ภาพก่อน/หลังบริการ ลูกค้าสามารถตรวจสอบรายงานหลังงานเสร็จได้

### การชำระเงิน

เวอร์ชันปัจจุบันรองรับการบันทึกการยืนยันชำระเงินหน้างานโดยลูกค้าและช่างทั้งสองฝ่าย แต่ยังไม่เชื่อมระบบธนาคารหรือ Payment Gateway จึงไม่ควรนำเสนอว่าเป็นการตรวจสอบธุรกรรมจริง

## 6. หลักการทำงานทางเทคนิค

AirClean ประกอบด้วย 3 ชั้นหลัก:

1. **Frontend — React, TypeScript และ Vite:** แสดงหน้าจอลูกค้าและช่าง รับข้อมูลจากฟอร์ม แผนที่ รายการงาน และโปรไฟล์
2. **Backend — ASP.NET Core 8 Web API:** ตรวจสอบข้อมูล ยืนยันตัวตนด้วย JWT และตรวจสิทธิ์ก่อนประมวลผลคำขอ เช่น การจอง การเปลี่ยนสถานะ การแชร์ตำแหน่ง และรายงานบริการ
3. **Database — MongoDB Atlas:** เก็บข้อมูลบัญชีผู้ใช้ ข้อมูลช่าง การจอง พิกัด รายงานบริการ เครื่องปรับอากาศ และงานกลุ่ม

แผนที่ใช้ Leaflet และ OpenStreetMap ส่วนการเผยแพร่ใช้ Render สำหรับ Frontend และ Backend

### ลำดับการจองและให้บริการ

`ระบุสถานที่ → ใส่งานและเวลาที่ต้องการ → เลือก/จับคู่ช่าง → ยืนยันงาน → ช่างรับงาน → นำทางและแชร์ตำแหน่ง → ให้บริการ → รายงานและยืนยันชำระเงิน`

รายละเอียดขั้นตอนการเลือกช่างและการรับงานต้องสอดคล้องกับรูปแบบตลาดบริการที่เลือกใช้ ดูหัวข้อ “ประเด็นที่ต้องตัดสินใจก่อนปรับระบบ” ด้านล่าง

## 7. สิ่งที่มีอยู่แล้วในโค้ดปัจจุบัน

- ระบบสมัครสมาชิก เข้าสู่ระบบ และ JWT
- เลือกบทบาท Customer, Technician หรือ Manager ตอนสมัครได้ แต่สมัครเป็น Admin โดยตรงไม่ได้
- หน้าโปรไฟล์แก้ไขชื่อและอีเมลได้ โดยบทบาทเป็นแบบอ่านอย่างเดียว
- ฟอร์มจองมีแผนที่ให้แตะเลือกหมุด หรือใช้ตำแหน่งปัจจุบัน
- แก้ไขบ้านเลขที่ ประเภทที่พัก ชื่ออาคาร ชั้น ห้อง และจุดสังเกตได้
- บันทึกที่อยู่ที่ใช้บ่อยไว้ใน Local Storage ของเบราว์เซอร์เครื่องนั้น
- ลูกค้าเลือกช่างจากรายการในฟอร์มจองปัจจุบันได้
- ติดตามตำแหน่งช่างบนแผนที่เมื่อมีพิกัด
- ช่างอัปเดตสถานะงาน ส่งรายงาน และยืนยันการชำระเงินหน้างานร่วมกับลูกค้าได้
- มีหน้าแสดงสมุดประวัติประจำเครื่อง และหน้าสำหรับสร้างคำของงานหลายเครื่อง

## 8. ช่องว่างสำคัญที่ควรพัฒนาต่อ

- **งานใกล้ช่าง:** ปัจจุบันช่างดูรายการที่ถูกผูกกับโปรไฟล์ของตน ยังไม่มีตลาดงานที่แสดงคำขอใหม่ใกล้ตำแหน่งช่างอย่างครบถ้วนพร้อมระยะทางและการรับงาน
- **รายได้และรายละเอียดหน้างาน:** ควรแสดงค่าตอบแทนที่เข้าใจง่าย ประเภทที่พัก และจำนวนเครื่องแบบเป็นข้อมูลแยกช่อง ไม่ควรให้ช่างต้องอ่านช่องข้อความอิสระเพื่อเดารายละเอียด
- **การนำทาง:** แผนที่ปัจจุบันแสดงหมุดตำแหน่งลูกค้าและช่าง แต่ยังไม่ได้คำนวณหรือวาดเส้นทางถนนแบบนำทางครบรูปแบบ ควรมีปุ่มเปิดเส้นทางภายนอกและแสดงตำแหน่งช่างระหว่างเดินทาง
- **การจับคู่ตามระยะทาง:** ข้อมูลพื้นที่ช่างปัจจุบันยังไม่ใช่ระบบคำนวณระยะทางและเวลาถึงจริง ต้องเพิ่มตำแหน่งหรือพื้นที่ให้บริการที่อัปเดตได้
- **ข้อมูลที่อยู่:** ที่อยู่ประจำเก็บในเบราว์เซอร์ ยังไม่ซิงก์ไปยังบัญชีบนอุปกรณ์อื่น
- **ความปลอดภัยของ Role:** ควรเพิ่มขั้นตอนอนุมัติสำหรับบัญชีช่างและผู้ดูแลอาคาร หากจะเปิดสมัครแบบสาธารณะ
- **การชำระเงินจริง:** ยังไม่มีการตรวจสอบธุรกรรมจากธนาคารหรือ Payment Gateway

## 9. ประเด็นที่ต้องตัดสินใจก่อนปรับระบบรับงาน

ในโค้ดปัจจุบัน ลูกค้าเลือกช่างแล้วจึงสร้างรายการจอง ส่วนแนวคิดให้ช่างเลือกงานในพื้นที่ต้องกำหนดให้ชัดว่าจะใช้รูปแบบไหน:

- **แบบ A — ลูกค้าเลือกช่างโดยตรง:** ลูกค้าเห็นช่างที่เหมาะสมและจองกับช่างคนนั้น ช่างจะเห็นงานที่ถูกส่งมาถึงตนและกดยอมรับหรือปฏิเสธ
- **แบบ B — ตลาดงานใกล้ตัว:** ลูกค้าส่งคำขอพร้อมสถานที่และรายละเอียดงานก่อน ระบบแสดงคำขอให้ช่างที่อยู่ในพื้นที่เลือกเข้ารับงาน แล้วลูกค้าติดตามช่างที่รับงานแล้ว

สองแบบนี้ส่งผลต่อการออกแบบหน้าจอ การจับคู่ช่าง และกฎ Backend จึงควรเลือกให้ตรงกับแนวคิดหลักก่อนสร้างระบบรับงานใกล้ตัวเต็มรูปแบบ

## 10. สรุป

AirClean ควรเริ่มต้นจากการทำให้ลูกค้าระบุสถานที่ จองบริการ และติดตามช่างได้สะดวก ขณะเดียวกันช่างควรเห็นงานใกล้ตัว รายละเอียดงาน และค่าตอบแทนได้ชัด พร้อมนำทางไปยังพิกัดลูกค้าได้โดยตรง ส่วนสมุดประวัติประจำเครื่องและการจัดการงานหลายเครื่องเป็นฟังก์ชันเสริมสำหรับผู้ใช้ที่ต้องการ ไม่ใช่ภาระที่ทุกคนต้องผ่านก่อนใช้บริการ
