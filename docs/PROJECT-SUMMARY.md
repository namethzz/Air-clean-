# AirClean — สรุปโครงการ

## 1. ภาพรวมโครงการ

**AirClean** เป็นเว็บแอปพลิเคชันสำหรับจองบริการล้างแอร์และจัดการงานบำรุงรักษาเครื่องปรับอากาศ โดยรวมการค้นหาช่าง การนัดหมาย การติดตามงาน รายงานบริการ และประวัติการดูแลเครื่องไว้ในระบบเดียว

ระบบแบ่งบทบาทเป็น 4 กลุ่ม ได้แก่ **Customer (ลูกค้า), Technician (ช่างแอร์), Manager (ผู้ดูแลอาคาร) และ Admin (ผู้ดูแลระบบ)** แต่ละบทบาทมีเมนูและสิทธิ์ต่างกัน

## 2. วัตถุประสงค์

1. ลดความยุ่งยากในการค้นหาช่างและจองบริการล้างแอร์
2. ให้ลูกค้าตรวจสอบสถานะการจองและติดตามช่างระหว่างเดินทางได้
3. จัดเก็บรายงานบริการและประวัติการบำรุงรักษาของเครื่องปรับอากาศ
4. รองรับการจัดการคำขอล้างแอร์หลายเครื่องสำหรับอาคาร
5. แบ่งบทบาทและสิทธิ์การใช้งานเพื่อลดการเข้าถึงข้อมูลที่ไม่เกี่ยวข้อง

## 3. ฟังก์ชันของแต่ละ Role

### Customer — ลูกค้า

- สมัครสมาชิก เข้าสู่ระบบ และออกจากระบบ
- แก้ไขชื่อและอีเมลในหน้าโปรไฟล์ แต่ไม่สามารถเปลี่ยนบทบาทเองได้
- ค้นหาช่าง กรองพื้นที่ และเรียงลำดับตามคะแนนหรือราคา
- ส่งคำขอจองบริการ พร้อมเลือกวัน เวลา และตำแหน่งให้บริการ
- ดูรายการจอง ติดตามสถานะ และดูตำแหน่งช่างเมื่อมีข้อมูล GPS
- ดูประวัติเครื่องปรับอากาศที่ผูกกับบัญชี
- ตรวจสอบและยืนยันรายงานบริการ
- ยืนยันการชำระเงินหน้างานร่วมกับช่าง หรือแจ้งปัญหาการชำระเงิน

### Technician — ช่างแอร์

- ดูรายการจองที่ผูกกับโปรไฟล์ช่างของตนเอง
- รับงานและปรับสถานะตามขั้นตอนที่ระบบกำหนด
- แชร์ตำแหน่ง GPS ระหว่างเดินทาง หากผู้ใช้อนุญาตการเข้าถึงตำแหน่ง
- สร้างรายงานบริการ เช่น ล้างแผ่นกรอง ทำความสะอาดคอยล์ และตรวจท่อน้ำทิ้ง
- บันทึกลิงก์รูปก่อนและหลังบริการ
- ยืนยันการชำระเงินหน้างานร่วมกับลูกค้า
- แก้ไขข้อมูลโปรไฟล์และออกจากระบบ

### Manager — ผู้ดูแลอาคาร

- ค้นหาช่างและดูรายการจองที่เกี่ยวข้องกับบัญชี
- ดูข้อมูลเครื่องปรับอากาศและประวัติบริการตามสิทธิ์
- สร้างคำขอแบบกลุ่ม โดยระบุอาคาร ที่อยู่ จำนวนเครื่อง และวันที่นัดหมาย
- ติดตามรายการงานกลุ่มและจำนวนเครื่องที่ดำเนินการแล้ว
- ดูรายงานบริการและจัดการโปรไฟล์

### Admin — ผู้ดูแลระบบ

- เข้าถึงข้อมูลหลายส่วนได้กว้างกว่าบทบาททั่วไป ตามสิทธิ์ที่ Backend กำหนด
- ดูรายการจอง เครื่องปรับอากาศ งานกลุ่ม และรายงานบริการ
- มีสิทธิ์ปรับสถานะการจองได้กว้างกว่าบทบาททั่วไป
- ใช้ API ระดับผู้ดูแลในส่วนที่ระบบเปิดสิทธิ์ไว้

> **หมายเหตุ:** ปัจจุบันยังไม่มีหน้า Admin Dashboard แยกที่ครอบคลุมการจัดการผู้ใช้และการอนุมัติบทบาททุกขั้นตอน การสร้าง Admin ต้องทำผ่านการตั้งค่าฝั่งเซิร์ฟเวอร์หรือการกำหนดข้อมูลในฐานข้อมูลอย่างระมัดระวัง

## 4. หลักการทำงาน

### ส่วนประกอบหลัก

1. **Frontend — React, TypeScript และ Vite:** แสดงหน้าจอ ฟอร์ม เมนูตามบทบาท รายการจอง แผนที่ รายงาน และโปรไฟล์
2. **Backend — ASP.NET Core 8 Web API:** ตรวจสอบข้อมูลและสิทธิ์ จัดการบัญชี การจอง สถานะงาน GPS รายงานบริการ และการยืนยันการชำระเงิน
3. **Database — MongoDB Atlas:** จัดเก็บบัญชีผู้ใช้ ข้อมูลช่าง การจอง เครื่องปรับอากาศ งานกลุ่ม รายงานบริการ รีวิว และข้อมูลที่ระบบใช้อ้างอิง
4. **Map — Leaflet และ OpenStreetMap:** แสดงแผนที่และข้อมูลตำแหน่ง
5. **Deployment — Render:** ใช้เผยแพร่เว็บไซต์ Frontend และ Backend API

### ขั้นตอนการทำงานตั้งแต่ต้นจนจบ

1. ผู้ใช้สมัครหรือเข้าสู่ระบบ Backend ตรวจบัญชีและรหัสผ่าน โดยรหัสผ่านถูกจัดเก็บเป็น Hash
2. เมื่อเข้าสู่ระบบสำเร็จ Backend ออก JWT ให้ Frontend แนบ Token เมื่อเรียก API
3. Frontend แสดงเมนูตามบทบาท และ Backend ตรวจสิทธิ์อีกครั้งก่อนดำเนินการ
4. ลูกค้าเลือกช่าง บริการ วันเวลา และสถานที่ แล้วส่งคำขอจองให้ Backend บันทึกลง MongoDB
5. ช่างรับงาน เปลี่ยนสถานะเป็นกำลังเดินทาง แชร์ตำแหน่งเมื่อได้รับอนุญาต ถึงหน้างาน และเริ่มให้บริการ
6. ช่างบันทึกรายงานบริการ หลังจากนั้นลูกค้าและช่างยืนยันการชำระเงินคนละฝั่ง
7. เมื่อทั้งสองฝ่ายยืนยันตรงกัน ระบบบันทึกสถานะเสร็จสิ้น และข้อมูลบริการที่ผูกกับเครื่องสามารถแสดงในประวัติย้อนหลังได้

### ลำดับสถานะงานตัวอย่าง

`รอยืนยัน → ยืนยันแล้ว → กำลังเดินทาง → ถึงหน้างาน → กำลังดำเนินการ → รอชำระเงิน → เสร็จสิ้น`

การจองอาจถูกยกเลิกหรือเข้าสู่สถานะมีปัญหาการชำระเงินได้ ตามเงื่อนไขของระบบ

## 5. เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี | หน้าที่ |
|---|---|---|
| Frontend | React, TypeScript, Vite | ส่วนติดต่อผู้ใช้ |
| Backend | ASP.NET Core 8 Web API | API และ Business Logic |
| Database | MongoDB Atlas | จัดเก็บข้อมูล |
| Authentication | JWT และ Password Hashing | ยืนยันตัวตน |
| Map | Leaflet และ OpenStreetMap | แผนที่และตำแหน่ง |
| Hosting | Render | เผยแพร่เว็บไซต์และ API |

## 6. ข้อจำกัดและสิ่งที่ควรพัฒนาต่อ

- หน้าสมัครอนุญาตให้เลือก Customer, Technician หรือ Manager ได้ แต่ไม่อนุญาตให้สมัคร Admin โดยตรง หากจะใช้งานจริงควรเพิ่มสถานะรออนุมัติโดย Admin สำหรับ Technician/Manager ก่อนเปิดสิทธิ์เต็มรูปแบบ
- เมนูงานหลายเครื่องใน Frontend ปัจจุบันยังแสดงให้ Customer ด้วย หากต้องการให้เฉพาะ Manager ใช้งาน ต้องปรับทั้งเมนูและกฎสิทธิ์ Backend ให้ตรงกัน
- การชำระเงิน Cash/PromptPay เป็นการบันทึกการยืนยันของลูกค้าและช่าง ยังไม่ตรวจสอบธุรกรรมธนาคารและไม่เชื่อม Payment Gateway
- รูปก่อนและหลังบริการรับเป็น URL ยังไม่มีระบบอัปโหลดและจัดเก็บไฟล์จริง
- ยังไม่มีระบบรีเซ็ตรหัสผ่าน การยืนยันอีเมล และ Push Notification
- ควรทดสอบการทำงานแบบ End-to-End และทบทวนความปลอดภัยก่อนเปิดให้ใช้งานจริงในวงกว้าง

## 7. สรุป

AirClean ช่วยเชื่อมโยงลูกค้า ช่างแอร์ และผู้ดูแลอาคารผ่านกระบวนการจองและติดตามงานแบบดิจิทัล โดยรวมข้อมูลไว้ในฐานข้อมูลเดียวและแบ่งสิทธิ์ตามบทบาท จุดสำคัญของระบบคือการติดตามสถานะบริการ รายงานหลังทำงาน และประวัติการบำรุงรักษา ซึ่งช่วยให้การจัดการงานล้างแอร์มีความเป็นระบบมากขึ้น
